# Проблемы
 
В текущей  реализации взаимодействие сервисов происходит синхронно. Отсюда вытекают следующие проблемы:
 - За один запрос к сервису ins-product-aggregator последнему необходимо опросить все страховые компании, чтобы сформировать 
 и вернуть в ответе данные со всех страховых компаний. Взаимодействие с каждой страховой компанией осуществлятся с разной скоростью.
 Все это время установленное с сервисом ins-product-aggregator соединение держится открытым, что приводит к неоправданному расходу
 ресурсов (в данном случае соединению из пула). 
 - Общее время опроса страховых компаний сервисом ins-product-aggregator может не уложиться в таймаут, отведенный для сетевого взаимодействия
 между сервисами внутри системы, что приведет к разрыву соединения и потере данных, частично полученных от страховых компаний.
 - Сложно масштабировать систему, так как сервисы жестко связаны синхронным взаимодействием.
 
# Риски
 - При разрывах соединения с сервисом ins-product-aggregator по таймауту теряются данные, уже полученные этим сервисом от части страховых компаний.
 Это ведет к устареванию информации в базах сервисов ins-comp-settlement и core-app, а следовательно использованию в своих бизнес-процессах
 неактуальных данных.
 - Использование неактуальных данных несет в свою очередь как репутационные, так и финансовые риски. Например, сервис core-app 
 предоставил партнерам через свой API устаревшие данные, или сервис ins-comp-settlement некорректно произвел рассчеты со страховыми
 компаниями.
